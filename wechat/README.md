# 同行账本 · 微信小程序开发版

原生 WXML/WXSS/JavaScript 小程序，与网页版复用同一套分账算法和 D1 账本服务。包括旅行列表、创建与设置、均分记账、分摊明细、成员、实际还款、邀请加入、归档及账号绑定。

## 现在即可体验：演示模式

1. 安装微信开发者工具，导入本目录 `wechat/`，识别 `project.config.json`。
2. 目前 AppID 为 `touristappid`，选择游客/无 AppID 开发模式。游客模式的可用性以开发者工具实际支持为准；如工具要求注册账号，请先取得测试/正式 AppID。
3. 保持 `miniprogram/config.js` 中 `mode: 'demo'`。无需安装小程序端 npm 依赖，也无需后端凭据。
4. 运行后可体验青岛三人示例旅行，并新增、编辑、删除支出、登记还款、归档或创建自己的演示旅行。
5. 演示数据仅存在当前设备的本地存储中，不与网页同步。在「我的账号」可重置。演示模式不支持真实账号绑定或向其他设备邀请。

本环境没有微信开发者工具或真实 AppID，已验证代码结构、JS 语法、页面控制逻辑和共享后端测试；**尚未经过微信开发者工具实际编译、真机测试或微信审核**。

## 注册后开启真实共享

采用小程序 → 微信云函数 → Sites 共享 API 的架构。客户端使用 `wx.cloud.callFunction`，云函数从 `cloud.getWXContext()` 获取 OPENID/APPID，而不是信任客户端提供的身份。后端验证云函数的 HMAC 签名、时间戳和一次性 nonce，再查询微信身份对应的账本用户。

参考：[腾讯云官方云函数调用指南](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)。这里采用的是微信云开发调用链，不能将前端参数里的 openId 当作登录凭据。

### 1. 小程序和云环境

- 注册微信小程序，取得真实 AppID。在 `project.config.json` 中替换 `touristappid`。
- 为小程序开启云开发，创建环境，并确认 AppID 与该环境关联。
- 在 `miniprogram/config.js` 中填写 `cloudEnv`，将 `mode` 改为 `'cloud'`。
- 使用开发者工具对 `cloudfunctions/travelLedger` 执行「上传并部署：云端安装依赖」。函数名保持 `travelLedger`。

### 2. 双端服务配置

通过各平台的私密环境变量配置界面填写，**不要把秘密写进源码、项目 JSON 或 GitHub**：

| 位置 | 变量 | 内容 |
| --- | --- | --- |
| Sites 运行时 | `WECHAT_APP_ID` | 真实小程序 AppID |
| Sites 运行时 | `WECHAT_GATEWAY_SECRET` | 至少 32 字节的随机共享密钥 |
| 微信云函数 | `LEDGER_API_ORIGIN` | `https://travel-billing-together.joyzheng03.chatgpt.site` |
| 微信云函数 | `LEDGER_GATEWAY_SECRET` | 与 Sites 的共享密钥完全相同 |

共享密钥只在两端服务器保存，不下发到小程序。此路径无需自建 `code2Session`/AppSecret 登录流程。更改配置后重新部署相关服务，确保云函数所在网络可以访问 Sites 地址。

缺少 AppID、密钥或数据库绑定时，`POST /api/mini` 返回 503；错误签名、非允许的 AppID、过期请求和重放请求会被拒绝。开发模式不会偷偷退回到真实服务或共享他人的身份。

### 3. 绑定已有网页版账号

1. 网页版使用自己的 ChatGPT 账号登录，点击右上角「微信同步」。
2. 生成十位绑定码，十分钟内在小程序「我的账号」输入。
3. 确认绑定：微信已有旅行和账单会原子合并到生成此码的网页版账号，包括重叠成员的分摊金额、垫付、还款、创建者权限。
4. 绑定后微信与网页使用同一身份、同一账本，修改互相可见。合并会更新相关旅行版本，旧编辑草稿须明确刷新后重试。

新码会使旧的未使用码失效，绑定码只允许一个微信身份领取。已经绑定的微信身份不支持直接更换网页版账号。合并后同一人的内部还款保留在历史中，对余额净影响为零；只有原归档旅行的成员仍可查看该旅行，账号合并不改变账本金额。

### 4. 邀请和同步

- 旅行创建者在小程序中生成邀请，使用「转发邀请给微信好友」。接收人进入加入页，只能看到旅行简介，确认加入后才可查看账单。
- 两端共享相同邀请令牌。网页版链接中的 `/join/令牌` 对应小程序的 `pages/join/index?token=令牌`；普通网页链接不会自动变成小程序码。
- 小程序账本打开时每十五秒刷新，页面返回和保存后刷新；没有离线写入队列。编辑页保留开始编辑时的版本，发生冲突时由用户选择刷新版本并保留草稿。

## 开发与验证

在仓库根目录运行：

```sh
npm run mini:build
npm run mini:check
npm run typecheck
npm test
npm run build
```

`mini:build` 从 `lib/core.ts` 生成小程序可用的 CommonJS 计算模块，避免两端分账逻辑分叉。展示金额与香港日期另有不依赖 Intl 的格式化适配。小程序页面使用原生组件，不依赖网页 React、CSS 或浏览器登录页面。

`mini:check` 检查六个页面配置、JS 语法与原生标签结构，不等同于官方编译器。后端新增迁移为 `drizzle/0001_worried_titania.sql`，不要修改已应用的旧迁移。

正式启用前，至少用两个真实微信账号和一个网页版账号验证：绑定前后共享账本、重复成员合并、微信好友邀请、跨设备记账、均分尾差、部分还款、撤销还款、并发冲突和归档权限，然后提交微信审核。

不包含微信支付、票据识别、订阅消息、自动催款或自动发布至微信。
